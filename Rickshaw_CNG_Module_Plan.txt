====================================================
MODULE 3 - RIDER TRIP & FARE ESTIMATION
====================================================

Goal:
Rider can post a trip request and see an estimated fare.

MongoDB Collection - tripRequests:
- riderId         (ObjectId ref users)
- pickup          ({ name, lat, lng })
- destination     ({ name, lat, lng })
- requestedTime   (Date)
- distanceKM      (Number)
- estimatedFare   (Number)
- status          (Enum: PENDING, MATCHED, NEGOTIATING,
                   ACCEPTED, ONGOING, COMPLETED, CANCELLED)
- createdAt       (Date)

Initial status: PENDING

Backend:
- POST /api/fare/estimate
  Input : pickup (lat,lng), destination (lat,lng)
  Output: distanceKM, durationMin, estimatedFare
- POST /api/trips
- GET  /api/trips/my

Fare Formula:
  distanceKM    = Haversine(pickup, destination)
  estimatedFare = 30 + (distanceKM x 15)
  Base fare     = 30 BDT
  Per KM rate   = 15 BDT

Frontend Pages:
- /rider/dashboard      (shows their trips)
- /rider/request-trip   (form for pickup + destination)

Frontend Components:
- TripRequestForm
- FareDisplay
- TripCard

Done when:
- System calculates and shows estimated fare
- Trip saved to MongoDB with PENDING status
- Rider can see their trip list

====================================================
MODULE 5 - FARE NEGOTIATION ENGINE
====================================================

Goal:
Driver makes offer. Rider counters or accepts.
Real time via Socket.io. Core innovation of the project.

MongoDB Collection - driverOffers:
- tripId      (ObjectId ref tripRequests)
- driverId    (ObjectId ref users)
- amount      (Number)
- message     (String, optional)
- status      (Enum: PENDING, COUNTERED, ACCEPTED,
               REJECTED, EXPIRED)
- createdAt   (Date)

Backend APIs:
- POST /api/offers
- GET  /api/offers/:tripId
- POST /api/offers/:offerId/counter
- PUT  /api/offers/:offerId/accept
- PUT  /api/offers/:offerId/reject

Socket.io Events:
  join-trip-room    -> joins room by tripId
  new-offer         -> offer-received    (to rider)
  counter-offer     -> counter-received  (to driver)
  accept-offer      -> offer-accepted    (both)
  reject-offer      -> offer-rejected    (to driver)

Negotiation Example:
  Estimated fare : 120 BDT
  Driver offer   : 150 BDT -> PENDING
  Rider counter  : 130 BDT -> COUNTERED
  Driver counter : 140 BDT -> COUNTERED
  Rider accepts  : 140 BDT -> ACCEPTED

Frontend Components:
- OfferForm
- NegotiationThread
- CounterOfferForm
- AcceptRejectButtons

Done when:
- Driver submits offer
- Rider sees it instantly (no page refresh)
- Rider can counter or accept
- Driver sees counter instantly
- Accepted offer triggers trip confirmation


====================================================
MODULE 6 - TRIP STATUS FLOW
====================================================

Goal:
Trip moves through stages after offer is accepted.

MongoDB Collection - trips:
- tripRequestId   (ObjectId ref tripRequests)
- riderId         (ObjectId ref users)
- driverId        (ObjectId ref users)
- agreedFare      (Number)
- actualFare      (Number)
- status          (Enum)
- startTime       (Date)
- endTime         (Date)
- createdAt       (Date)

Status Flow:
  PENDING -> MATCHED -> NEGOTIATING -> ACCEPTED
  -> DRIVER_ARRIVING -> ONGOING -> COMPLETED

Who updates what:
  DRIVER -> DRIVER_ARRIVING, ONGOING, COMPLETED
  RIDER  -> CANCELLED (before ONGOING only)

Backend:
- PUT /api/trips/:id/status

Frontend Components:
- TripStatusBar
- DriverTripControls  (Start Trip / End Trip buttons)
- RiderTripView

Done when:
- Rider accepts -> trip document created
- Driver marks trip started and completed
- Rider sees status update in real time

====================================================
MODULE 9 - LIVE DRIVER TRACKING
====================================================

Goal:
Rider sees driver moving on the map in real time.

MongoDB Collection - locations:
- driverId    (ObjectId ref users)
- lat         (Number)
- lng         (Number)
- updatedAt   (Date)

Flow:
  Driver GPS -> emit every 3 sec -> Socket.io Server
  -> broadcast -> Rider map marker moves

Socket Events:
  Driver emits : update-location { lat, lng, tripId }
  Rider gets   : driver-location-update { lat, lng }

Done when:
- Driver marker moves every 3 seconds on rider map
- Tracking stops when trip COMPLETED
