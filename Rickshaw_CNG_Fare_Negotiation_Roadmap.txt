- Leaflet.js
- Routing service such as OSRM

Deployment:
- Vercel for React frontend
- Render/Railway for backend
- MongoDB Atlas for database


PROJECT GOAL
------------
Build an application where:
1. A rider posts a trip request.
2. The system estimates the fare.
3. The system finds drivers whose routes overlap with the rider's route.
4. Drivers can make fare offers.
5. Riders and drivers negotiate the fare.
6. The rider accepts an offer.
7. The trip is tracked.
8. The rider submits the actual fare and rating.
9. Admin manages the whole system.

PHASE 5 - FARE ESTIMATION ENGINE
---------------------------------
Start with a simple formula.

Example:

Estimated Fare =
Base Fare + (Distance x Per KM Rate)

Example:
Base Fare = 30 BDT
Per KM = 15 BDT
Distance = 5 KM

Estimated Fare = 30 + (5 x 15)
                = 105 BDT

Later you can consider:
- Distance
- Travel time
- Time of day
- Vehicle type
- Demand

API example:

POST /api/fare/estimate

Input:
- Pickup
- Destination

Output:
- Distance
- Estimated travel time
- Estimated fare

PHASE 7 - ROUTE-OVERLAP MATCHING
---------------------------------
This is the main special feature of the project.

Example:

Rider:
Mirpur -> Farmgate

Driver:
Uttara -> Dhanmondi

If both routes share a significant portion:

Common route / Rider route x 100
= Route overlap percentage

Example:
Rider route = 8 KM
Common route = 5 KM

Overlap = 5 / 8 x 100
        = 62.5%

Set a threshold such as:
- 50% or higher = potential match

System should:
1. Find suitable drivers.
2. Get/construct their routes.
3. Compare rider and driver routes.
4. Calculate overlap.
5. Rank drivers.
6. Show best matches first.

Example:

Driver A - 82% match
Driver B - 67% match
Driver C - 54% match
